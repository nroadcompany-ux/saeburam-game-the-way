# 1️⃣ 설계 철학 전환

## 기존 설계 ❌
```
성경 사건을 시간순으로 나열
001 아담 → 002 가인 → 003 노아 → ...
사용자: "100개 사건을 모두 경험하는 게임"
```

## 새로운 설계 ✅
```
플레이어의 감정 상태에서 출발
오늘의 마음: "두렵다"
    ↓
성경 사건 추천: 모세, 여호수아, 베드로...
    ↓
하나님의 질문 → 깨달음 → 회개 → 순종 → Legacy

사용자: "나의 현재 마음에서 성경으로 들어가는 여정"
```

```
[HOME 화면]
```

```
○ 길을 잃었다
○ 교만해졌다
○ 하나님을 찾고 있다
○ 잘 모르겠다

[선택 안 하기]
```

**의미:**
- 매일 사용자는 "자신의 현재 상태"를 인식하고 시작
- 성경을 "읽는" 것이 아니라 "들어가는" 것

# 3️⃣ Chapter 시각화 방식 확정

## 기존 3가지 옵션 vs 새로운 구조

```
❌ 옵션 A/B/C 단독 선택이 아니라

✅ 감정 선택 → 추천 카드 3~5개 → 카드 스택

구조:

【 감정 선택 】
  "두렵다"
    ↓
【 추천 여정 카드 】
  [1] 모세 — "나는 할 수 없습니다"
  [2] 기드온 — "정말 저입니까?"
  [3] 베드로 — "물 위에서 흔들리다"
  [4] 여호수아 — "강하고 담대하라"
    ↓
【 카드 스택 스와이프 】
  한 번에 1개씩 경험
    ↓
【 선택 후 진입 】
  Chapter Flow 시작
```

**왜 이 구조인가:**
- 감정이 선택의 진입점 (개인화)
- 추천된 3~5개만 보기 (인지 부하 최소화)
- 카드 스택 (터치 친화적)
- 100개 모두 노출하지 않음 (오버로드 방지)

# 4️⃣ CORE_BIBLE_100 역할 변경

## 기존 ❌
```
CORE_BIBLE_100 = 게임 진행 콘텐츠
("100개를 모두 경험하세요")

구조:
사용자 → 001 진행 → 002 진행 → ... → 100 진행
```

## 새로운 ✅
```
CORE_BIBLE_100 = 감정별 추천 사건 데이터베이스
("당신의 감정에 맞는 성경 사건들")

구조:
감정 "두려움" → DB 쿼리 → 모세, 여호수아, 베드로... (5개)
감정 "분노" → DB 쿼리 → 가인, 요나, 다윗... (5개)
감정 "외로움" → DB 쿼리 → 요셉, 엘리야, 다윗... (5개)
```

**의미:**
- 100개 모두 게임 진행 콘텐츠가 아님
- 백그라운드 데이터베이스로 활용
- 감정별 매칭으로 개인화 추천

# 5️⃣ Wisdom Point 표시 방식 변경

## 기존 ❌
```
"Wisdom Point: 280점"
"레벨 5"
"상위 1%"

→ 경험치처럼 보임
```

## 새로운 ✅
```
Wisdom Point는 내부 점수로만 계산
사용자에게는 노출하지 않음

대신 보여주는 것:
✓ 깨달음 기록: 9가지
✓ 순종 기록: 15번
✓ Legacy 변화: 6개월 여정 기록

사용자가 보는 것:
"당신은 9번 깨달았고,
15번 순종했고,
6개월의 여정을 기록했습니다"

→ 게임 점수가 아니라 영적 여정으로 표현
```

**원칙:**
- Wisdom은 흔적이지 경험치가 아님
- 깨달음 + 순종 + 기록이 눈에 보이는 결과

# 6️⃣ Discernment Engine 트리거 확정

## 감지 조건
```
반복 횟수: 3회 이상
감지 기준: 주제 + 감정 + 관계 (복합)

예:
- 003 | 가인 | "분노" + "형제 관계" + "판단"
- 015 | 요나 | "분노" + "타인 관계" + "의로움"
- 027 | 다윗 | "분노" + "왕 관계" + "자부심"
- 035 | 이사야 | "분노" + "민족 관계" + "낙담"

시스템: "어? 이 패턴 자주 보이네?"
→ Discernment 질문 제공
```

## 제시 방식
```
❌ 팝업 금지
   ("패턴 발견!" 이라는 경고)

✅ Legacy 작성 중 자연스럽게 제안
   기도 쓰는 도중 문맥에 맞춰
   "혹시 이것도 관련이 있을까요?" 정도로 제시

방식:
사용자가 기도 쓰는 중
  ↓
시스템이 패턴 감지
  ↓
하단에 작은 텍스트로 제시
  ↓
사용자 선택: [더 탐색] / [지금은 아니요]
  ↓
강압 없음, 자연스러운 흐름
```

# 7️⃣ Legacy 공유 정책

## MVP 단계
```
✅ Legacy 저장: 필수
✅ Legacy 조회: 필수
✅ Legacy 수정: 필수

❌ Legacy 공유: 보류
❌ 커뮤니티: 보류
```

## 구현 원칙
```
MVP:
- 기본값: 비공개
- 사용자 개인 조회만 가능
- 수정 기능 (원본 보존 + 수정 이력)
- 삭제 불가 (영구 저장)

MVP 이후:
- 선택적 공유 기능 추가
- 친구 공유, 그룹 공유, 공개 중 선택
- 공개된 Legacy 커뮤니티 표시

이유:
MVP 단계에서는 개인의 기록 안정성이 최우선
공유 기능은 안정적 기반 위에서 추가
```

# 1️⃣1️⃣ 핵심 원칙 재확인

## THE WAY의 진정한 정의

> **THE WAY는 성경을 시간순으로 소비하는 게임이 아니다.**
>
> **THE WAY는 오늘의 마음에서 출발해**  
> **성경 속 하나님의 질문으로 들어가는 여정이다.**
>
> 플레이어는 성경을 구경하지 않는다.  
> **자신의 삶을 들고 성경 안으로 들어간다.**
>
> 모든 기록은 언젠가 간증이 된다.  
> 모든 결정은 언젠가 지혜가 된다.

# 1️⃣2️⃣ 질문이 있을 때

```
개발팀이 궁금한 점:

Q1: "감정을 여러 개 선택할 수는 없나?"
A: 오늘은 하나만. 내일은 다른 감정을 선택할 수 있음.
   매일 새로운 여정.

Q2: "100개를 모두 경험하려면 몇 개월 걸리나?"
A: 그게 목표가 아님. 
   사용자가 필요한 때 필요한 감정의 성경을 만나는 것.
   100개는 백그라운드 데이터베이스.

Q3: "Wisdom Point를 사용자에게 보여주지 않으면 게임 맛이..."
A: 게임이 아니라 여정.
   깨달음 + 순종 + 기록이 눈에 보이는 변화.

Q4: "MVP에 X 기능은 정말 필요 없나?"
A: 필요하면 기획팀과 상의.
   우선순위: 첫 번째 영혼의 회개 > 모든 기능 완성도

→ 모르는 부분은 기획팀에 연락 주세요!
```
