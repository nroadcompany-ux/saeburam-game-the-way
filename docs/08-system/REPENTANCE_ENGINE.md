# PART 1. 엔진 정의

## 1.1 Repentance Engine이란

> 플레이어가 자신의 죄와 실패를 마주하고,  
> 하나님께 돌아오는 과정을 지원하는 엔진.

Repentance Engine은 THE WAY의 가장 중요한 엔진 중 하나다.  
회개는 처벌이 아니라 **복귀**다.  
시스템은 정죄하지 않는다. **초대한다.**

## 1.2 핵심 원칙

| 원칙 | 내용 |
|------|------|
| 강요 없음 | 회개는 강요되지 않는다. 항상 초대다 |
| 문 열림 | 언제나 돌아올 문이 열려 있다 |
| 정죄 없음 | 시스템은 절대 정죄하지 않는다 |
| 실패도 기록 | 회개하지 못한 것도 Legacy가 된다 |
| 나선형 | 같은 죄도 깊이를 더하며 반복될 수 있다 |
| 간증으로 | 모든 회개 기록은 언젠가 간증이 된다 |

# PART 2. 회개 흐름 전체 구조

## 2.1 6단계 흐름

```
1단계 — 질문 (Question)
    하나님의 질문이 먼저 온다
    ↓
2단계 — 깨달음 (Awakening)
    "이것이 나의 이야기다"는 인식
    ↓
3단계 — 회개 (Repentance)
    "나는 잘못했다"는 고백
    ↓
4단계 — 기도 (Prayer)
    하나님 앞에서의 대화
    ↓
5단계 — 실천 (Obedience)
    방향을 바꾸는 구체적 행동
    ↓
6단계 — 간증 (Testimony)
    Legacy에 기록, 언젠가 나눔
```

## 2.2 흐름의 핵심 원칙

각 단계는 **순서대로 진행되지 않을 수 있다.**  
플레이어에 따라:
- 2→3→1 (깨달음이 먼저, 질문은 나중에)
- 3→4→3 (회개하고 기도하다가 다시 더 깊이 회개)
- 5→6 (실천 중에 간증을 발견)

엔진은 순서를 강요하지 않는다.  
하지만 어느 단계에 있든 **다음 단계로의 초대**는 항상 있다.

# PART 3. 단계별 상세 설계

## STAGE 1 — 질문 (Question)

**목적:** 회개의 문을 여는 질문

### 질문 유형

| 유형 | 예시 | 활성화 조건 |
|------|------|------------|
| 직접 회개 질문 | "넌 지금 무엇을 숨기고 있는가?" | CAT_02 활성 시 |
| 간접 인식 질문 | "반복되는 패턴이 무엇인지 보이는가?" | 반복 실패 감지 시 |
| 관계 질문 | "아직 용서하지 못한 사람이 있는가?" | CAT_04 활성 시 |
| 교만 질문 | "넌 지금 하나님 없이도 된다고 생각하는가?" | CAT_06 활성 시 |

### 질문 트리거 조건

```
자동 트리거:
- 같은 현실 퀘스트를 3회 이상 실패
- 5일 이상 Daily Question에 응답 없음
- 같은 회개 영역이 2회 이상 기록됨

사용자 시작:
- "회개하기" 버튼 직접 탭
- 묵상 중 회개 감지 (키워드 기반, 향후)
```

---

## STAGE 2 — 깨달음 (Awakening)

**목적:** "이것이 나의 문제다"는 자기 인식

### 깨달음의 3가지 유형

**유형 A — 거울 깨달음**
> "이 성경 인물의 모습이 나다"

- 사울의 자기합리화 → 나의 자기합리화
- 요나의 도피 → 내가 피하고 있는 것
- 베드로의 부인 → 내가 부인하는 것

**유형 B — 패턴 깨달음**
> "나는 같은 것을 반복하고 있다"

- Legacy 데이터에서 반복 패턴 감지
- "이것이 세 번째입니다" 알림 (정죄가 아니라 인식)

**유형 C — 대조 깨달음**
> "하나님의 기준과 내가 너무 다르다"

- 산상수훈 vs 내 삶
- 십계명 vs 내 행동
- 사랑의 정의 vs 내 사랑의 방식

### 깨달음 기록 구조

```
awareness_type    : 'mirror' | 'pattern' | 'contrast'
insight_text      : "나는 항상 결과가 좋을 때만 순종한다"
triggered_by      : question_id / chapter_number
felt_intensity    : 1~5 (얼마나 불편했는가)
```

## STAGE 3 — 회개 (Repentance)

**목적:** 하나님 앞에서의 고백

### 회개의 5단계 심화 구조

```
L1 — 인식     : "나는 무언가를 잘못했다"
L2 — 명명     : "그것은 ___이다" (구체적으로)
L3 — 고백     : "하나님 앞에서 말한다"
L4 — 전환     : "이제 방향을 바꾼다"
L5 — 기록     : "Legacy에 남긴다"
```

### 회개 UI 흐름 (텍스트 기반)

```
플레이어 화면 순서:

1. "오늘 무엇이 마음에 걸리나요?" (개방형)
      ↓
2. "그것을 조금 더 구체적으로 말할 수 있나요?" (심화)
      ↓
3. "하나님께 직접 말하듯이 써보세요" (고백 공간)
      ↓
4. "이제 무엇을 바꾸고 싶나요?" (전환)
      ↓
5. "이것을 Legacy에 남기겠습니까?" (기록 선택)
```

### 회개 영역 카테고리

```
sin_area 코드:
- PRIDE          : 교만 / 자기중심
- ANGER          : 분노 / 상처 주기
- LUST           : 정욕 / 잘못된 욕망
- FEAR           : 두려움 / 불신
- DISOBEDIENCE   : 순종 거절
- UNFORGIVENESS  : 용서 거절
- DISHONESTY     : 거짓 / 숨김
- IDOLATRY       : 우상 / 하나님 대체
- NEGLECT        : 방치 / 무관심
- COMPARISON     : 비교 / 질투
- OTHER          : 기타 (자유 입력)
```

### 반복 회개 처리

```
동일 sin_area 에서의 반복 회개:

1회 : 일반 회개 흐름
2회 : "이전에도 이것을 다루었습니다" 알림 + 이전 기록 보여줌
3회 : "깊이 씨름해야 할 것 같습니다" + 특별 질문 제공
5회 이상 : Discernment Engine 연동 → 근본 원인 탐색 질문
```

---

## STAGE 4 — 기도 (Prayer)

**목적:** 회개 후 하나님과의 대화

### 기도 유형과 흐름

**회개 기도 (가장 중요)**
```
구조:
- 감사 (하나님을 인정함)
- 고백 (회개한 내용 반복)
- 간구 (변화를 위한 도움 요청)
- 감사 (받아들임)
```

**기도 작성 가이드 (시스템 제공)**
```
빈 페이지가 아닌 구조 제공:

"하나님, 오늘 저는..."      → 고백 시작
"제가 잘못한 것은..."       → 구체적 고백
"저를 도와주세요..."        → 간구
"감사합니다, 왜냐하면..."   → 감사
```

### 기도 응답 추적

```
prayer_status:
- 'praying'     : 기도 중
- 'answered'    : 응답 받음 (사용자 표시)
- 'trust'       : 아직 응답 없지만 신뢰 중
- 'unclear'     : 응답인지 모르겠음

answered_at     : 응답받은 날짜
answer_note     : "이렇게 응답받았습니다"
```

---

## STAGE 5 — 실천 (Obedience)

**목적:** 회개가 방향 전환으로 이어짐

### 회개 후 현실 퀘스트 생성 원칙

회개의 내용에 따라 **자동 퀘스트가 제안**된다.

```
sin_area → 권장 퀘스트 유형:

UNFORGIVENESS  → "오늘 그 사람에게 한 가지 친절을 베푼다"
ANGER          → "오늘 화를 냈던 사람에게 사과한다"
PRIDE          → "오늘 내가 틀렸다고 인정해야 할 것을 인정한다"
FEAR           → "두려워서 미뤘던 것을 오늘 한 발 내딛는다"
DISHONESTY     → "숨겼던 것을 한 사람에게 솔직하게 말한다"
DISOBEDIENCE   → "알고 있었지만 안 했던 것을 오늘 한다"
```

### 실천의 2가지 유형

**즉각 실천 (Today Quest)**
- 오늘 안에 할 수 있는 것
- 예: "지금 그 사람에게 문자 한 통 보낸다"

**지속 실천 (Ongoing Quest)**
- 반복적 변화가 필요한 것
- 예: "이번 주 매일 아침 분노 일지를 쓴다"
- 7일 후 점검 알림

---

## STAGE 6 — 간증 (Testimony)

**목적:** 회개와 변화가 Legacy가 되고, 언젠가 간증이 됨

### 간증 생성 조건

```
자동 간증 제안:
- 같은 sin_area에서 3회 이상 회개 + 마지막이 'restored'
- 현실 퀘스트가 10회 이상 완료된 영역
- "나는 달라졌다"를 직접 기록한 경우

간증 구조:
1. 이전의 나  : "나는 이런 사람이었다"
2. 만남       : "이 질문/말씀이 나를 흔들었다"
3. 씨름       : "나는 이렇게 싸웠다"
4. 변화       : "나는 이렇게 달라졌다"
5. 현재       : "지금 나는 이런 사람이다"
```

### 간증과 공유

```
is_testimony = true 로 표시된 Legacy:
- 개인 간증 페이지에 정리됨
- 선택적으로 공동체와 공유 가능
- 공유 시 익명 처리 옵션

공유 원칙:
- 강요 없음
- 부분 공유 가능 (일부만 공개)
- 언제든 비공개로 전환 가능
```

# PART 4. 반복 패턴 분석

## 4.1 패턴 감지 알고리즘

```
분석 대상:
- 같은 sin_area의 반복 횟수
- 회개 후 obedience 완료율
- 회개 주기 (얼마만에 같은 것을 다시 회개하는가)
- 깨달음 깊이 변화 (depth_level 변화 추이)

패턴 유형:
A — 성장 패턴  : 같은 영역이지만 깊이가 증가
B — 순환 패턴  : 같은 수준에서 반복
C — 정체 패턴  : 회개 후 실천 없음이 반복
```

## 4.2 패턴에 따른 대응

```
성장 패턴 (A)
  → "이 영역에서 깊이 성장하고 있습니다"
  → 심화 질문 제공

순환 패턴 (B)
  → "같은 자리에서 반복하고 있는 것 같습니다"
  → Discernment Engine 연동: 근본 원인 탐색 질문

정체 패턴 (C)
  → "회개 후 실천이 어려우신가요?"
  → 더 작고 쉬운 퀘스트 제안
  → "오늘 한 가지만" 접근
```

# PART 5. Discernment Engine 연동

## 5.1 연동 조건

```
Repentance Engine → Discernment Engine 호출:

1. 같은 sin_area에서 5회 이상 회개
2. 회개 후 실천 완료율이 20% 미만
3. 회개 주기가 7일 미만으로 반복
```

## 5.2 Discernment 질문 예시

```
패턴이 감지될 때 제공하는 깊이 있는 질문:

- "이 패턴이 언제부터 시작되었는가?"
- "이 죄가 너에게 주는 것이 무엇인가?"
- "이것을 끊지 못하게 하는 두려움이 있는가?"
- "이것 뒤에 더 깊은 것이 있지는 않은가?"
- "이것이 정말 죄인가, 아니면 상처인가?"
```

# PART 6. 엔진 상태 다이어그램

```
회개 엔진 상태:

[대기]
  ↓ 질문 수신 / 사용자 시작
[질문 단계]
  ↓ 인식 발생
[깨달음 단계]
  ↓ "이것이 나의 문제다"
[회개 단계]
  ├── 고백 완료 → [기도 단계]
  └── 고백 보류 → [대기] (문은 항상 열려 있음)
[기도 단계]
  ↓ 기도 기록
[실천 단계]
  ├── 퀘스트 완료 → [간증 단계]
  ├── 퀘스트 실패 → [기록 + 대기] (실패도 기록)
  └── 퀘스트 연기 → [대기] (재알림)
[간증 단계]
  ↓ Legacy 기록
[완료]
  → 더 깊은 질문으로 다시 [질문 단계]
```

# PART 7. UI/UX 설계 원칙 (회개 관련)

## 7.1 절대 해서는 안 되는 것

| ❌ 금지 | 이유 |
|---------|------|
| "회개하지 않으면 잠금" | 강요는 진짜 회개가 아니다 |
| 회개 횟수 공개 | 수치심을 이용하는 것 |
| "이번이 몇 번째입니다" (정죄 톤) | 인식이지 정죄가 아니어야 함 |
| 시간 제한 | 회개는 강요되지 않는다 |
| 회개 기록 삭제 허용 | 모든 기록은 간증이 된다 |

## 7.2 반드시 해야 하는 것

| ✅ 필수 | 이유 |
|---------|------|
| 언제나 "지금 시작하기" 버튼 제공 | 문은 항상 열려 있다 |
| 이전 회개 기록 조용히 보여주기 | 내 여정을 볼 수 있게 |
| 실패도 기록되도록 | 실패도 Legacy다 |
| 응원 없이 동행 | "잘하셨어요" 대신 "함께합니다" |
| 다음 단계 초대 (강요 아님) | 항상 다음 걸음이 있다 |
